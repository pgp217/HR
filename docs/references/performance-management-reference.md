# 성과관리(OKR) 기능 참고 자료 — 에이치닷(h.place) 제품 화면

나중에 이 앱(pgp217/hr)에 성과관리 기능을 만들 때 참고하려고, 에이치닷(h.)이라는
외부 HR 솔루션의 제품 체험 페이지(`h.place/product-experience?solution=performance`)
화면 5장을 보고 기록해둔 것. 우리 코드가 아니라 참고용 메모다.

## 1. 전체 구조

좌측 사이드바에 "캠페인" 단위로 성과관리 사이클을 묶는다. 예: `[샘플] 성과관리 캠페인
(22.01.01~22.12.31)`. 캠페인 하위 메뉴:

- **목표 보드** — 목표를 트리(상위/하위 목표) 구조로 보여주는 메인 화면
- **활동 피드**
- **승인 요청**
- **성과 대시보드** (하위 메뉴 있음)
- **목표 현황**
- **캠페인 설정** (하위 메뉴 있음)

상단 탭으로는 "내 목표 / 팀 목표 / 전체 목표"를 전환한다.

더 큰 제품 전체로 보면 목표(성과경영) 외에도 리뷰 / 미팅 / 인사평가 / 인재 프로필 /
관리자 설정 탭이 나란히 있어서, 성과관리가 더 큰 인사 스위트의 한 모듈로 붙어있는
구조다.

## 2. 목표 보드 (Goal Board)

- 상단에 목표 총 개수(예: "7개의 목표")와 전체 달성률 진행바("78% 달성 중")
- 상태별 카운트: 대기 / 진행중 / 문제발생 / 완료 4단계
- 목표 리스트는 표 형태이면서 트리 구조(하위 목표를 +/- 로 펼치고 접음).
  예: "전사 인사평가 제도 개선"(101%) 아래에 "외부 컨설팅 진행 준비"(93%), "정기
  인사평가 제도 개편"(100%) → 그 아래 다시 "평가제도 교육자료 제작"(81%) 같은 3단
  depth까지 내려감.
- 표 컬럼: 목표명, 배지("내 목표" 등), 담당자(아바타+이름), 조직 태그(색상별 pill —
  경영총괄본부/인사총무팀/경영기획팀 등), 마감일, 진행률 바 + %, "..." 메뉴
- 검색창, 정렬 아이콘, "가중치 설정" 버튼, "신규 생성" 버튼이 우측 상단에 있음
- 달성률이 100%를 넘는 목표도 존재(101%) — 초과 달성을 허용하는 방식으로 보임

## 3. 목표 생성 마법사 (6단계)

모달로 뜨는 위저드, 상단에 단계 탭이 계속 보여서 어느 단계인지 항상 알 수 있음.

1. **목표** — 목표 내용(리치텍스트: 굵게/밑줄/취소선/목록/링크/이모지/체크박스/이미지),
   "지표 불러오기" 링크(기존 지표 재사용), 상위 목표 설정(추천값 자동 제시 — 예:
   "(추천) 전사 HR 제도 개선 (기업대표)"), 하위 목표 설정(선택), 성과 지표 종류
   (정성/정량 등, 필수), 가중치(%, 숫자 입력)
2. **계획 설정**
3. **공개 범위** — 누구에게 공개할지(상세 패널에 "담당자 및 담당자의 모든 조직장에
   공개" 같은 문구로 결과가 보임)
4. **난이도** — 레벨 0 / 레벨 1 / 레벨 2 같은 난이도 등급을 목표별로 선택. 목표마다
   난이도를 다르게 매길 수 있다는 설명 툴팁이 붙어있음
5. **템플릿** — (화면 캡처 없음, 이름만 확인)
6. **승인자** — 1차 승인자 설정(필수, 드롭다운 — 예: "기업대표 (기업)"). "이전/취소/
   생성" 버튼으로 마무리

## 4. 목표 상세 패널

목표를 클릭하면 우측에서 슬라이드로 열리는 상세 패널(별도 창으로도 열 수 있음):

- 목표명 + 조회수 아이콘
- "목표 달성 현황: 0% (0%) 달성 중" + 진행바
- 액션 버튼: 계획 관리 / 과제 확인 / 과제 수정
- 하위 탭: 상세 정보 / 코멘트 / 변경 이력
- **기본 정보** 아코디언: 실행 기간, 담당자(이름+소속), 공개 범위, 조직 라벨, 가중치,
  난이도
- **상세 설명** 아코디언(본문 텍스트, 비어있으면 "-")

## 5. 우리 앱에 옮길 때 눈여겨볼 점

- **목표 트리(상위/하위)** — 우리 `Candidate`/`OnboardingTask` 처럼 평평한 리스트가
  아니라, 목표끼리 부모-자식 관계를 갖는 구조. 새 컨텍스트/타입 설계 시 `parentGoalId`
  류의 자기참조 관계가 필요.
- **가중치 총합 100% 규칙** — 화면에 "가중치 총합을 100%로 설정하세요" 안내가 있었음.
  형제 목표들의 가중치 합이 100%가 되도록 검증하는 로직이 있는 듯.
- **단계형 생성 마법사** — 우리 `TalentDbForm`처럼 한 번에 긴 폼을 보여주는 대신,
  목표/계획/공개범위/난이도/템플릿/승인자로 단계를 쪼갬. 필드가 많아지면 참고할만한
  패턴.
- **승인자 워크플로 + 승인 요청 메뉴** — 목표 생성 시 승인자를 지정하고 별도
  "승인 요청" 메뉴에서 처리 — 우리 연차/출장 승인 흐름(`ApprovalsManager`)과 유사한
  패턴이라 재사용 가능.
- **상태 4단계(대기/진행중/문제발생/완료)** — 우리 `RecruitStage`처럼 좁은 stage
  enum 대신, 진행 상태와 "문제발생" 같은 예외 상태를 분리해서 관리.
